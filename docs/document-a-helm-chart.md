# How to Document a Helm Chart

This guide shows you how to document a Helm chart in your [app of apps fork](/docs/applications/get-started/app-of-apps-setup/#fork-the-app-of-apps-repository). Each chart's `README.md` is generated by [helm-docs](https://github.com/norwoodj/helm-docs), from a `README.md.gotmpl` template and the `# --` comments in its `values.yaml`. Never edit `README.md` by hand, since the next render overwrites it.

It assumes you've already written the chart, as in [Write the App](/docs/applications/add-edit-or-remove-an-app/#write-the-app).

## Write the README Template

Create a `README.md.gotmpl` next to the chart's `Chart.yaml`, with this skeleton, replacing every `<...>`:
```markdown
# `<chart>` Helm Chart Reference

<intro>

## What's Inside

- **[<file 1>](<file 1>)**: <important facts about file 1>
- **[<file 2>](<file 2>)**: <important facts about file 2>
- ...one bullet per file in the chart

{{ template "chart.valuesSection" . }}

## Upstream Dependencies

- **[`<dependency>`](<link>)**: <what the chart needs from it>
```

### Intro Section

Replace `<intro>`, right under the title, with one sentence saying what the chart deploys.

If the chart deploys an external chart (listed under `dependencies:` in its `Chart.yaml`), its `values.yaml` only overrides a few of that chart's keys. Add two sentences to `<intro>`:
- `## Values` lists only what this chart sets.
- For every other key, read the external chart's `values.yaml`, with a link to it.

For example, in [`charts/monitoring/blackbox-exporter/README.md.gotmpl`](../charts/monitoring/blackbox-exporter/README.md.gotmpl):
```markdown
The [`blackbox-exporter` chart](./) deploys [blackbox-exporter](https://github.com/prometheus/blackbox_exporter) via the upstream `prometheus-blackbox-exporter` chart, probing every private and public tool endpoint for HTTP reachability. [Values](#values) lists only what this chart sets. For every other key, read the upstream [`values.yaml`](https://github.com/prometheus-community/helm-charts/blob/main/charts/prometheus-blackbox-exporter/values.yaml).
```

### What's Inside Section

Under `## What's Inside`, add one bullet per file in the chart, including every values file. Describe each file in one phrase, with only the facts not obvious from its name. For example, in [`charts/gateway-api/httproute/README.md.gotmpl`](../charts/gateway-api/httproute/README.md.gotmpl):
```markdown
- **[templates/httproute.yaml](templates/httproute.yaml)**: binds to both the `http` and `https` listeners of the target `Gateway`
- **[values.schema.json](values.schema.json)**: rejects an empty `host` or `backendRefs.default.name`
- **[argocd-httproute-values.yaml](argocd-httproute-values.yaml)**: ArgoCD UI and API. Routes `Content-Type: application/grpc` requests to `argocd-server-grpc`, the rest to `argocd-server`
```

### Values Section

Keep `{{ template "chart.valuesSection" . }}` as is, between `## What's Inside` and `## Upstream Dependencies`. helm-docs replaces it with a `## Values` section, holding one table row per documented value. For example, with two documented values:
```markdown
## Values

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| prometheus-blackbox-exporter.serviceMonitor.defaults.module | string | `"http_2xx"` | Probe module for every target, expecting an HTTP 2xx. |
| prometheus-blackbox-exporter.serviceMonitor.targets | list | `[]` | Endpoints to probe, one `ServiceMonitor` each. Injected by the catalog via `appParams`, from `domains.hcl`. |
```

### Upstream Dependencies Section

Under `## Upstream Dependencies`, add one bullet per component the chart needs, such as the catalog unit that injects its values via `appParams`, or another chart. Say what the chart needs from it. Don't list the components that depend on the chart. For example, in [`charts/monitoring/blackbox-exporter/README.md.gotmpl`](../charts/monitoring/blackbox-exporter/README.md.gotmpl):
```markdown
- **[`app_of_apps`](https://github.com/ConsciousML/terragrunt-template-catalog-eks/blob/main/units/eks/addons/argocd/app_of_apps/terragrunt.hcl)** (catalog): injects `serviceMonitor.targets` from [`domains.hcl`](https://github.com/ConsciousML/terragrunt-template-catalog-eks/blob/main/pipelines/dev/eks/domains.hcl)
- **[`kube-prometheus-stack`](../kube-prometheus-stack)**: Alertmanager routes these alerts by their `component: uptime` label
```

## Document the Values

In the chart's `values.yaml`, add a `# --` comment on the line right above each key the chart sets. Its text becomes the key's Description in `## Values`. A key without one gets no row. For example, in [`charts/gateway-api/httproute/values.yaml`](../charts/gateway-api/httproute/values.yaml):
```yaml
# -- Must set `external-dns.alpha.kubernetes.io/scope` to `public` or `private`, else no DNS record.
annotations: {}
```

A plain `#` comment above the `# --` one stays out of `## Values`. Use it for a note aimed at whoever edits the chart, such as why a value is set this way. For example, in the same file:
```yaml
# backendRefKey points into backendRefs, not at the backend itself, so appParams can
# override just a name (e.g. compose "<release>-grafana") without restating the whole
# rules list.
# -- Route rules. `matches` is Gateway API `HTTPRouteMatch` syntax. `backendRefKey` is a key into `backendRefs`.
rules: []
```

To group the rows of `## Values` into one table per topic, add a `# @section -- <name>` line under the `# --` comment. Each section renders as a `### <name>` table. For example, `charts/gateway-api/httproute/values.yaml` splits its keys between `Gateway` and `Route`:
```yaml
gateway:
  # -- Target `Gateway` name. Set by the shared `*-gateway-values.yaml` in `extraValueFiles`.
  # @section -- Gateway
  name: ""
# -- `HTTPRoute` name.
# @section -- Route
name: ""
```

helm-docs renders these two keys as:
```markdown
## Values

### Gateway

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| gateway.name | string | `""` | Target `Gateway` name. Set by the shared `*-gateway-values.yaml` in `extraValueFiles`. |

### Route

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| name | string | `""` | `HTTPRoute` name. |
```

If a key holds an object or a list too long to read in the Default column, add a `# @default -- see values.yaml` line under the `# --` comment. It replaces the rendered default with that text. For example, in [`charts/monitoring/blackbox-exporter/values.yaml`](../charts/monitoring/blackbox-exporter/values.yaml):
```yaml
  # -- Resource requests and limits.
  # @section -- Exporter
  # @default -- see values.yaml
  resources:
    requests: { cpu: 15m, memory: 100Mi }
    limits: { memory: 100Mi }
```

helm-docs renders this key as:
```markdown
| Key | Type | Default | Description |
|-----|------|---------|-------------|
| prometheus-blackbox-exporter.resources | object | see values.yaml | Resource requests and limits. |
```

If the chart deploys an external chart, the keys it overrides sit under the dependency's name in `values.yaml`, like `resources` above under `prometheus-blackbox-exporter`. Document only those overrides, not the keys left at the external chart's default.

Rows follow the order of the keys in `values.yaml`, so order them as you want them read.

If the chart receives a value from the catalog through `appParams` (see [Pass Terraform Values to an App](/docs/applications/pass-terraform-values-to-an-app/)), always document its key, and say it's injected by the catalog. Leave it empty in `values.yaml`, like `host` in `charts/gateway-api/httproute/values.yaml`:
```yaml
# -- Hostname. Injected by the catalog via `appParams` (from `domains.hcl`), never set per instance.
# @section -- Route
host: ""
```

## Render the README

Commit your change and push it to a pull request. CI's `helm-docs` job renders the `README.md` of every chart from its template and values, and pushes the result as a `docs: render chart READMEs with helm-docs` commit to your branch. Pull it before your next push:
```bash
git pull
```

To check the result before pushing, render the READMEs locally from the root of your app of apps fork, with the same options as CI:
```bash
HELM_DOCS_IGNORE_NON_DESCRIPTIONS=true helm-docs --sort-values-order file
```

Then check the chart's `README.md`: every key you documented must have a row in `## Values`. If one is missing, check its `# --` comment sits on the line right above the key, or right above its `# @section` and `# @default` lines.
